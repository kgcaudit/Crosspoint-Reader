## 1. 무엇을 만드는가

휴대폰에 **이미 있는** 만화책 · 웹툰 파일을 OLO eBook 에서 읽는다. EPUB · TXT · PDF 와 같은 서재 · 같은 이어 읽기 ·
같은 책갈피.

**하지 않는 것** — 온라인 소스 · 확장 · 다운로드 · 스토어. Tachiyomi(2024-01)와 Kotatsu(2025-11)는 온라인 소스
때문에 권리자 경고를 받고 멈췄다. 이 앱은 **로컬 파일 전용**이고 그 원칙을 여기 남긴다.

## 2. 조사 요약 (다른 앱)

Mihon · Kotatsu · Librera 는 GitHub 원본을 직접 읽었다. Perfect Viewer · CDisplayEx · ComicScreen · Moon+ · 리디 · 네이버는
검색 요약만 볼 수 있었다(이 환경의 네트워크가 막았다). 출처는 조사 보고서 원문에 있다.

| 거의 모든 앱에 있음(필수) | 대부분(사실상 필수) | 일부 | 드묾 |
|---|---|---|---|
| CBZ · CBR · 그림 폴더, 왼→오 · 오→왼, 웹툰 세로 스크롤, 확대(두 번 누르기 · 두 손가락), 누름 구역, 화면 · 폭 맞춤, 다음 권 이어 보기, 이어 읽기, 자연 정렬(2 다음 10) | 가로 두 쪽, 여백 자르기, 미리 읽기, 볼륨키, 바탕 검정/흰색, 작품마다 보기 방식 기억, CB7 | 펼침면 나누기, 색 필터 · 흑백, 웹툰 옆 여백, 웹툰 자동 판별, 자동 스크롤 | 칸 단위 보기(Kindle · Play 북 — 출판사 데이터나 기계학습이 있어야 한다) |

국내 앱에서 가져올 것:
- **리디**: 만화는 넘겨 보기, 웹툰은 스크롤이 기본이다. 스크롤 보기에서는 두 쪽 · 넘김 효과를 끈다. 일본 만화는 방향을 반대로 둔다.
- **네이버 시리즈**: 진행 막대도 읽는 방향을 따라간다.
- **오→왼에서 누름 구역이 뒤집히지 않는 것**이 사용자가 가장 헷갈려하는 점이다.

## 4. 우리 구조에 놓는 법

- **`:document`(순수 Kotlin) 에 `comic/`** — 만화 하나의 쪽 목록.
  - CBZ/ZIP 은 기존 `ZipReader` 가 `SeekableSource` 위에서 **목차만 읽고 필요한 쪽만** 꺼낸다(통째로 복사하지 않는다 — 1GB
    파일에서 느리고 공간을 먹는다).
  - 그림 폴더는 SAF 폴더의 그림 파일들이다.
  - 쪽 크기는 기존 `ImageHeader` 가 머리만 읽어 안다. 디코드 없이 웹툰 판별 · 띠 나누기 · 두 쪽 묶기를 **기기 없이 시험**한다.
  - 자연 정렬, 다음 권, `ComicInfo.xml` 읽기(Series · Number · Title · Manga=YesAndRightToLeft · Pages/FrontCover ·
    DoublePage). 깨진 XML 은 버리고 연다(CLAUDE.md 규칙 6).
- **안드로이드 쪽(0.34.0 에서는 `:app` 의 `ComicBook` · `ComicReader`)** — 계획은 새 모듈 `:reader-comic` 이었으나, 서재 · 표지 보관소 · 진도가 모두 `:app` 에 있어 C1 은 그 옆에 두었다. 웹툰 띠 풀기(C2)가 커지면 모듈로 뺀다.
- 원래 계획: — 풀기(`BitmapFactory` / 긴 그림은 `BitmapRegionDecoder` 띠), 메모리 예산 안의
  캐시, 앞뒤 2~3장 미리 읽기, 화면(쪽 넘김 · 웹툰). 넘김 효과(`CpPageTurn`) · 누름 구역 · 볼륨키 · 밝기 · 보기 판은 이미
  있는 부품을 그대로 쓴다.
- **위치는 글자 오프셋 대신 "쪽 + 쪽 안 세로 비율"**. 웹툰은 "몇 번째 그림의 몇 %" 로 저장한다. 화면 폭 · 기둥 폭을
  바꿔도 자리가 미끄러지지 않는다(규칙 3 의 뜻을 그대로).
- **`null` 과 기본값을 구분한다**(규칙 5). 보기 방식 · 방향은 다음 순서로 정한다. 앞 단계가 "정하지 않음" 이면 다음 단계로
  간다: 책에 직접 고른 값 → ComicInfo → 쪽 모양 판별 → 앱 기본.
- **큰 그림의 위험**: 800×30000 한 장을 통째로 풀면 96MB 다. 하드웨어 캔버스 한도(약 100MB) · 텍스처 한도(4096/8192) 에
  걸려 꺼지거나 검게 나온다(Mihon 이슈 #830 · #1910 · #1973). 띠로만 풀고, 화면 밖 띠는 내려놓는다. 띠 풀기가 깨지는
  JPEG 는 줄여서 통째로 푸는 길로 되돌아간다.

## 7. 결정할 것 (권고는 ★)

1. **형식 범위 · 순서**
   - ★가. C1 은 CBZ/ZIP · 그림 폴더(순수 Kotlin, APK +0). CB7 · CBR 은 C4 에서 Explorer 의 네이티브 디코더(7z · UnRAR, arm64)를 가져온다.
     UnRAR 허가는 읽기만 허용한다 — Explorer 와 같은 조건.
   - 나. CBR 은 넣지 않는다.
   - 다. CBR 을 C1 부터 넣는다.
2. **보기 방식(쪽 넘김 · 웹툰)** — ★자동(쪽 모양 판별 + ComicInfo) + 책마다 고르면 기억 / 늘 처음에 묻기.
3. **넘기는 방향** — ★왼→오 기본, ComicInfo 가 오→왼이면 오→왼, **질(시리즈)마다 기억** / 앱 전체 설정 하나(Explorer 방식).
4. **쪽 밖 바탕** — ★어두운 바탕(만화 앱 대부분, 그림이 떠 보인다) / 지금 지면색(배경 설정)을 따름.
5. **서재** — ★"만화" 칸에 질 단위로(폴더 = 질, 안의 권 · 회차는 들여씀) / 다른 책과 낱권으로 섞기.
6. **쪽 넘김 효과** — ★책과 같은 설정(말림 등)을 따름 / 만화는 밀기 고정. 웹툰은 효과 없음(스크롤).
7. **웹툰 폭** — ★휴대폰은 꽉 채움, 태블릿 · 가로는 가운데 기둥(폭 조절) / 늘 꽉 채움.
