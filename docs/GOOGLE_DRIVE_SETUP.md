# 구글 드라이브 이어 읽기 — 구글 클라우드 등록 (0.57.0)

"다른 기기에서 이어 읽기" 는 구글 계정으로 드라이브의 **앱 전용 공간**(appDataFolder)을 쓴다. 이 연결이 되려면 구글 클라우드에
"이 앱(패키지 이름 + 서명)" 을 한 번 등록해야 한다. 등록 전에 켜면 앱이 "이 판은 아직 구글 드라이브 연결이 준비되지 않았습니다(앱 등록
필요)." 라고 알리고 꺼진 채 남는다.

**비밀값은 없다.** 안드로이드는 클라이언트 ID 를 앱에 넣지도 않는다 — 구글이 패키지 이름과 서명 지문으로 앱을 알아본다. 비밀번호 ·
키를 이 저장소에 넣을 일도, 세션에 알려 줄 일도 없다.

## 1. 프로젝트 만들기

1. <https://console.cloud.google.com/> → 위쪽 프로젝트 고르기 → **새 프로젝트** → 이름 `OLO eBook`.
2. **API 및 서비스 → 라이브러리** → "Google Drive API" → **사용**.

## 2. 동의 화면(OAuth 동의 화면)

1. **API 및 서비스 → OAuth 동의 화면**(새 화면에서는 "Google 인증 플랫폼 → 브랜딩").
2. 사용자 유형 **외부**. 앱 이름 `OLO eBook`, 지원 메일 · 개발자 메일은 본인 메일.
3. **데이터 액세스(범위)** 에 `https://www.googleapis.com/auth/drive.appdata` 하나만 더한다. 구글이 "민감하지 않은 범위" 로
   분류한다 — 보안 심사가 없다.
4. 게시 상태:
   - **테스트**: 테스트 사용자로 넣은 계정(본인)만 쓸 수 있다. 바로 써 볼 수 있다.
   - **프로덕션 게시**: 누구나. 민감하지 않은 범위만 쓰므로 브랜드 확인 정도로 끝난다.

## 3. 안드로이드 클라이언트

**사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID → 안드로이드**를 서명 키마다 하나씩 만든다.

| 무엇 | 패키지 이름 | SHA-1 |
|---|---|---|
| 지금 보내 드리는 APK(`-devkey`, 저장소의 공개 개발 키) | `io.github.kgcaudit.oloebook` | `E3:21:7A:DC:3F:39:B7:28:6F:12:6D:5E:6A:D5:5A:22:92:0A:E7:44` |
| 디버그 빌드(`.debug`) | `io.github.kgcaudit.oloebook.debug` | 위와 같음(같은 개발 키) |
| 비공개 키로 서명한 APK(PC 에서 만든 것) | `io.github.kgcaudit.oloebook` | PC 에서 `keytool -list -v -keystore <비공개 키 파일>` 의 SHA1 |

Play 스토어에 올리면 Play 가 다시 서명한다 — 그때는 Play Console 의 "앱 서명 키 인증서" SHA-1 도 더한다.

## 4. iOS 클라이언트(iOS 세션)

같은 프로젝트에 **OAuth 클라이언트 ID → iOS**(번들 ID)를 만든다. 앱 전용 공간은 **프로젝트마다** 따로라, 다른 프로젝트의 클라이언트를
쓰면 iOS 와 안드로이드가 서로의 기록을 보지 못한다. iOS 는 이 클라이언트 ID 와 역방향 클라이언트 ID(URL 스킴)를 앱 설정에 넣는다
(공개 값).

## 5. 확인

1. 휴대폰에서 앱 정보 → 다른 기기에서 이어 읽기 → 켬 → 계정 고르기 → 허용.
2. "마지막으로 맞춘 때" 가 "오늘 …" 이면 된 것이다. 다른 기기도 같은 계정으로 켜면 "함께 읽는 기기" 에 보인다.
3. 드라이브 웹(drive.google.com) → 설정 → 앱 관리에 "OLO eBook" 이 "숨겨진 앱 데이터" 와 함께 보인다. 거기서 데이터를 지울 수도 있다.
