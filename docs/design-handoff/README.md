# OLO 디자인 시스템 — 인계 묶음

OLO eBook(이 저장소 `android/`)이 쓰는 디자인을 **다른 앱 세션(Android Cycle 등)에 넘기려고** 모은 것이다.
값은 모두 실제 코드에서 옮겼다. 코드가 원본이고, 이 문서가 코드와 다르면 코드가 맞다.

- 원본 코드: `android/ui-design/src/main/kotlin/io/github/kgcaudit/reader/ui/design/`
  (`CpTheme.kt` 색 · 글자 · 치수, `CpComponents.kt` 부품, `CpIcons.kt` 선 아이콘, `CpCover.kt` 표지)
- 이 시스템의 처음 출처는 같은 사용자의 **OLO Explorer** 앱이다(`kgcaudit/Filezilla-Client` 의
  `docs/OLO-Design-System.md`). OLO eBook 은 그 값을 **바꾸지 않고** 옮겼다 — 여러 앱이 홈 화면에서 한 식구로
  보여야 하기 때문이다. 새 앱도 같은 원칙을 따르면 된다.

| 파일 | 내용 |
|---|---|
| `design-board.png` | 한 장 요약: 밝은 · 어두운 색 토큰, 글자 단계, 치수, 부품 |
| `icon/` | 실행 아이콘(OLO-Design 생성물: 적응형 아이콘 벡터 3개 + 설정) · `preview.png` |
| `screens/` | 앱 시험이 찍은 본보기 화면(시험용 가짜 책만 — 실제 사용자 책은 없다) |

## 1. 실행 아이콘

![아이콘](icon/preview.png)

- **적응형 아이콘**(`icon/ic_launcher.xml`): 바탕 · 앞 그림 · 흑백(안드로이드 13 테마 아이콘) 세 겹.
- **원본은 OLO-Design 이다**(kgcaudit/OLO-Design `appicons/launcher.py --app ebook`). 앱은 생성물을 그대로 넣고 손으로
  고치지 않는다(파일 머리 "Do not edit by hand"). 마크를 바꾸려면 디자인 세션에 청한다. 지금 것은 2e3b100(0.56.3, 사양 `ICON_REQUEST_EBOOK.md`).
- **바탕**(`ic_launcher_background.xml`): 왼쪽 위가 밝은 클레이 그라데이션 — 계열 모든 앱이 같은 바탕이다.
- **앞 그림**: 펼친 하드커버 + 책갈피 끈(0.56.3). 각진 표지 판(흰 22% 채움, 윤곽 없음) · 쪽(흰 40% 채움) · 굵기 강약 있는
  흰 붓 획 윤곽(가장 굵은 곳 9/512) · 쪽 두께 선 · 글줄 3줄 · 책등 한 획 · 책 아래로 늘어진 흰 끈. 계열(폴더 · 재생 · 달력)과 같은
  재료 — 반투명 흰 채움 + 붓 획. 안전 원 안(가장 먼 점 140.3/512, 안전 반지름 156.4).
- 흑백 겹(`ic_launcher_monochrome.xml`)은 앞 그림과 같은 도형이다. 색은 시스템이 입힌다.
- 시험(`AppWalkthroughTest`): 바탕이 주황 · 책등이 흰 획 · 쪽 안이 반투명 흰 채움 · 쪽 윤곽 + 글줄 3줄 · 끈이 책 아래로 · 마크 전체가 안전 원 안.

**타일 색 — 뜻이 있는 색**(목록 앞머리 네모. 쓰는 자리에서 고르지 않는다. 흰 그림을 얹으므로 다크에서 더 밝다)

| 뜻 | 밝은 | 어두운 |
|---|---|---|
| 폴더 | `#B95B3B` | `#D1734F` |
| 문서 · PDF · TXT · 책(EPUB) | `#55606B` | `#6E7A86` |
| 그 밖 | `#7A7168` | `#938A80` |

EPUB 은 색이 아니라 **그림**으로 가른다(0.32.2, 계열 FILEKIND 의 EBOOK): 문서 회청 위에 OLO-Design 의 두 톤 펼친 책
`ic_tile_book.xml` 을 그대로 얹는다(색을 입히지 않는다). 0.32.1 까지 쓴 청록은 계열에서 소스 코드(CODE)의 색이다.

**색을 정한 까닭**(바꾸기 전에 읽을 것)
- 따뜻한 **클레이 브랜드 + 아이보리 웜톤 중립색**. 차가운 회색 위의 따뜻한 강조색은 실수처럼 보인다.
- 클레이는 `#B95B3B`. 처음 값 `#C5613F` 위의 흰 글자가 4.07:1 로 WCAG AA(4.5:1)에 못 미쳐 5% 어둡게 했다.
  대비를 붙드는 시험(`ContrastTest`)이 있다. (아이콘 바탕은 글자가 없어 옛 값 그대로다.)
- 강조색으로 **글자**를 쓸 때는 `accentText`. 브랜드 클레이 글자는 팝업(3.72) · 고른 행(3.58)에서 4.5:1 에 못 미쳐
  글자에만 한 단계 짙게(다크는 밝게) 두었다 — 브랜드 색째 바꾸면 단추가 다른 OLO 앱과 달라진다.
- `error` 는 브랜드와 **색상 자체**를 갈라 크림슨으로 둔다. 이웃한 주황빨강이면 지우기 단추가 브랜드처럼 보인다.
- "다르기만 한 색"(타일)과 "뜻이 있는 색"(역할)을 섞지 않는다.

## 3. 글자

**시스템 글꼴**을 쓴다(삼성 "글꼴 스타일"을 바꾼 사람에게 앱만 다른 글꼴이면 어색하다. UI 만을 위해 수 MB 를 싣지 않는다).
제목만 줄이고 본문은 Material 크기 — 제목이 크면 팝업이 주변보다 두 배 큰 글자로 뜬다.

## 6. 설계 규칙 (모든 새 화면에 적용)

1. **위계는 들여쓰기로 보인다.** 한 행이 다른 행에 속하면 자식 행은 **부모 행의 글자가 시작하는 자리**에서 시작한다
   (`childIndent` · `levelIndent`). 같은 자리에서 시작하면 같은 급의 선택지로 읽힌다. 같은 급은 들이지 않는다.
   새 목록 화면은 시험에서 좌표로 잰다.
2. **그림은 자르지 않는다.** 칸 크기는 같게, 그림은 원래 비율로 칸 안에 가장 크게, 줄은 밑면을 맞춘다(책꽂이처럼).
3. **대비**: 글자와 바탕은 WCAG AA 4.5:1 이상. 강조색 위 글자도.
4. **다크 모드는 토큰 한 곳에서.** 화면은 역할 이름만 쓴다.
5. **고른 상태는 색만이 아니라 화면 읽기에도 알린다**(`selectable`, 단추마다 이름).
6. **한 줄 권수 · 칸 폭은 화면 폭에서 낸다.** 가로 화면에서 고정 권수로 두면 그림이 화면보다 커진다.
7. **소리는 움직임이 일어난 자리에서 난다**(2026-10-05 사용자 결정, OLO eBook 0.48.0 넘김 소리에 처음 적용).
   화면에서 무언가가 한쪽에서 움직이면 그 소리도 그쪽에서 시작해 움직임을 따라 쓸려 간다 — 손끝 · 눈 · 귀가 같은 이야기를 한다.
   - **움직이는 것을 따른다, 누른 자리가 아니다.** 책 넘김: 왼→오 책의 다음 쪽은 오른쪽 종이가 넘어가니 오른쪽에서, 이전 쪽은
     왼쪽에서. 오→왼 만화는 반대. 다른 예: 오른쪽에서 열리는 옆 판은 오른쪽에서, 왼쪽으로 밀어 지운 항목은 왼쪽으로.
   - **쓸림**: 시작 +0.7(움직임이 시작된 쪽) → 끝 −0.3(가운데를 조금 지남). −1 왼쪽 · +1 오른쪽. 끝까지 한쪽에 고정하면
     자주 듣는 소리에 한쪽 귀가 피곤하다.
   - **세기**: 같은 세기 법칙(cos/sin)에 √2 를 곱해 가운데가 원래 크기와 같게, 큰 쪽은 1.0 에서 멈춰 잘림이 없게.
   - **좌우가 진짜 좌우일 때만**: 이어폰 · 가로 화면 · 폭 600dp 이상(펼친 폴더블 · 태블릿). 세로로 든 휴대폰 스피커는 위 · 아래라
     좌우로 나눈 소리가 위아래로 갈라진다 — 그때는 가운데.
   - **설정 항목을 따로 두지 않는다.** 모노가 필요한 사람은 휴대폰 접근성의 "모노 오디오" 가 알아서 합친다.
   - 원본 소리는 모노 한 벌만 두고 쓸린 소리는 앱이 처음 쓸 때 만들어 캐시에 둔다(APK 를 키우지 않고, 소리를 바꿀 때 고칠 파일이
     하나). 코드: `PageTurnFx.kt` 의 `turnSide` · `spatialTurnSound` · `turnSweep` · `sweepStereo`.

8. **판은 나온 자리에서 움직여 나타나고, 그리로 돌아간다**(2026-10-22 사용자 확정, OLO eBook 0.55.0). 판이 그 자리에 "툭"
   나타나면 무엇이 어디서 열렸는지 눈이 따라가지 못한다. 값은 `CpMotion.kt` 한 곳에 있다 — 판마다 따로 적지 않는다.
   - 곡선: 들어올 때 `cubic-bezier(0.05, 0.7, 0.1, 1)`(빠르게 나와 천천히 멈춤), 나갈 때 `cubic-bezier(0.3, 0, 0.8, 0.15)`.
     나가는 쪽을 늘 더 짧게.

   | 판 | 어디서 | 열림 | 닫힘 |
   |---|---|---|---|
   | 읽기 메뉴 위 · 아래 막대 | 위는 위에서, 아래는 아래에서 미끄러짐 + 흐림 풀림 | 250ms | 200ms |
   | 보기 카드(태블릿) | 보기 단추 쪽(오른쪽 아래)에서 0.9 → 1 로 커짐 | 250ms | 150ms |
   | 보기 판(휴대폰) | 진행 막대 위로 펼쳐짐 | 250ms | 200ms |
   | 목차 · 독서노트 · 찾기 · 설정 | 태블릿 옆 판: 오른쪽에서 밀려 옴 + 뒤 막 서서히 / 휴대폰: 오른쪽에서 밀려 옴 | 350 / 300ms | 200ms |
   | 메모 · 각주 · 듣기 판 | 아래에서 올라옴 + 뒤 막 서서히 | 300ms | 200ms |
   | 팝업 · 서재 더 보기 판 | 0.95(더 보기는 0.9) → 1 로 커지며 나타남, 더 보기는 ⋮ 쪽에서 | 200ms | 150ms |

   - 리더의 판(막대 · 보기 · 목차 · 독서노트 · 찾기 · 설정)과 서재 더 보기 판은 닫힐 때도 움직인다. 앱이 `if` 로 띄우는 판(팝업 · 메모 ·
     각주 · 듣기 판)은 지금은 열릴 때만 움직이고 닫힐 때는 바로 사라진다(0.55.0).
   - 리더 밖에서 화면 전체가 바뀌는 것(태블릿의 서재 찾기 · 앱 정보)은 움직이지 않는다 — 판이 아니라 화면이 바뀌는 것이다.
   - 같은 무리 안에서 바뀌는 판(목차 → 설정 → 글꼴처럼 옆 판 안의 넘어감)은 움직이지 않고 갈아 끼운다.
   - 휴대폰의 "애니메이션 제거" 를 켜면 모두 바로 나타난다(Compose 가 길이를 0 으로 줄인다).
9. **판과 지면 사이에는 경계가 있다**(0.55.0). 판 색이 종이와 거의 같아(아이보리 · 밝은 테마) 경계가 흐렸다. 판 가장자리에
   1dp 선(`divider`) + 지면 쪽으로 10dp 옅은 그림자(검정 15% → 0). 선은 판 안쪽에 그어 판 높이를 늘리지 않는다(`cpEdge`).
   떠 있는 카드는 그림자 16dp + 1dp 테두리.
10. **태블릿에서 짧은 설정 판은 연 단추 위의 카드다**(0.55.0). 폭 420dp, 연 단추 쪽 끝에 붙는다. 화면 폭 전체로 늘이지 않는다 —
    양옆이 비어 보이고, 판이 본문을 다 가려 설정을 바꾼 결과를 볼 수 없다. 긴 목록(목차 · 독서노트)은 오른쪽 옆 판(400dp).

## 7. 작업 방식 (OLO eBook 세션에서 사용자가 정한 것)

- **구상안 이미지 → 결정 · 조정 → 확정 → 코딩.** 구상안은 실제 디자인 부품으로 그려, 구상안과 완성 화면이 다르지
  않게 한다. 선택지는 나란히 보이고 권고안을 표시하며, 결정할 것을 번호로 묻는다. 완성 뒤 확정 구상안과 나란히 대조한다.
- 사용자와의 말은 모두 **우리말**. 코드 주석도 한국어로 "무엇이 아니라 왜".
