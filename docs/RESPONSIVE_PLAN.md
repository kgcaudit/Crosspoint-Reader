# 반응형 배치 체계 (0.46.0, 2026-10-05 사용자 결정)

휴대폰 · 폴더블 · 태블릿에서 화면을 어떻게 나누는지의 규칙. 새 화면을 만들거나 고칠 때 이 표를 먼저 본다.
0.45 까지는 "태블릿이냐" 하나로만 갈라, 태블릿이면 휴대폰 화면을 가운데 600dp 에 그대로 옮겨 양옆이 비었다.

## 등급 — 지금 창의 폭 (Material 3 창 크기 등급)

| 등급 | 폭 | 예 | 배치 |
|---|---|---|---|
| 좁음 `Compact` | 600dp 미만 | 휴대폰 세로, 폴더블 바깥 화면 | 한 판, 줄 목록 |
| 중간 `Medium` | 600–839dp | 펼친 폴더블 세로, 작은 태블릿 | 한 판, 목록은 표지 격자 |
| 넓음 `Expanded` | 840dp 이상 | 펼친 폴더블 가로, 태블릿 | 두 판 — 왼쪽 고정 정보(320dp), 오른쪽 목록 |

높이도 본다: **높이 480dp 미만이면 폭과 상관없이 좁음처럼**(줄 목록). 휴대폰 · 바깥 화면을 가로로 돌리면 폭은 넓어도
높이가 393dp 안팎이라, 정보를 얹은 격자 · 두 판은 목록이 화면 밖으로 밀린다.

코드: `cpWidthClass()` · `cpRoomy()`(격자 · 두 판을 쓸 만한가) · `cpTwoPane()`(두 판) — `ui-design/CpAdaptive.kt`,
시험은 `AdaptiveTest`. `cpTablet()`(가장 짧은 변 600dp 이상)은 "기기가 태블릿인가" — 리더의 옆 판 · 큰 표지처럼 기기에
딸린 것에만 쓴다.

## 화면별

| 화면 | 좁음 · 낮은 창 | 중간 | 넓음 |
|---|---|---|---|
| 서재 | 격자 · 목록 · 책장 | 같음, 칸 수만 늘어남 | 같음 |
| 작품(만화) | 줄 목록 | 위 작품 정보 · 아래 권 표지 격자 | 왼쪽 작품 판(큰 표지 · 이어 읽기) · 오른쪽 권 격자 |
| 설정 · 앱 정보 | 전체 폭 | 600dp 가운데 (글과 단추가 멀어지지 않게) | 같음 |
| 독서 기록 (0.51.0) | 한 줄로 내려 읽기 | 600dp 가운데 | 두 판 — 왼쪽 타일 · 달력(320dp), 오른쪽 다 읽은 것 · 가장 오래 읽은 것 |
| 리더 | 화면 전체 | 화면 전체, 두 쪽 보기는 설정 | 화면 전체, 목차 · 책갈피는 오른쪽 옆 판(400dp) |
| 웹툰 | 그림 폭 기본 100%(밀대로 40~100%) | 가운데 기둥, 기본 70% | 같음 — 두 판으로 나누지 않는다. 웹툰은 한 줄로 내려 읽어 옆에 둘 내용이 없다(0.47.0 결정 ⑥) |

## 두 쪽 보기의 혼자인 쪽 (종이책 규칙)

표지는 뒤 쪽 자리(왼→오 책은 오른쪽, 오→왼 만화는 왼쪽), 혼자 남은 마지막 쪽은 앞 쪽 자리, 가로로 긴 펼침면 그림은
가운데. 순수 코어 `SpreadSlot` 이 정하고 만화 · PDF 가 함께 쓴다.

## 새 화면을 만들 때

1. 세 등급(+ 낮은 창)에서 각각 어떻게 서는지 구상안에 그린다 — 휴대폰만 그리면 태블릿이 휴대폰을 늘인 화면이 된다.
2. 두 판의 왼쪽은 고정 정보(제목 · 표지 · 주 단추), 오른쪽은 굴러가는 목록. 왼쪽 판이 넘치면 그 판만 굴린다.
3. 좌표로 잰다: 넓음에서 목록이 왼쪽 판 오른쪽에 서는지, 중간에서 격자가 한 줄에 나란히 서는지(`ComicReaderAppTest`).
